P0 — 让它像个「能用的终端」P0✅ 已实现

  • 1
    多标签 + 分屏
    SwiftTerm 支持多个 LocalProcessTerminalView，用 TabView / 自绘分屏。当前单会话是最大硬伤。
    SwiftTerm最高优先
  • 2
    字号调节 + 主题
    ⌘+/⌘- 调字号，内置几套配色（前景/背景/ANSI 调色板）。
    SwiftTerm
  • 3
    复制/粘贴/滚动区搜索
    SwiftTerm 有选区 API，补 ⌘F 搜索。
    ⌘F
  • 4
    最小配置文件
    ~/.config/voiceghostty/config —— 字体、配色、快捷键、语音语言列表。先支持 5 个键即可。
    config

P1 — 把语音护城河挖深（核心差异化）P1

  • 5
    落地步骤 4：接 Claude API 做 NL2Command ★
    NL2Command.swift 现为占位。system prompt 严格约束「只输出一条命令 + 一句中文解释」，结果进待确认区。比补分屏更能定义产品。
    Claude API路线图 #4最该先做
  • 6
    命令上下文感知
    把 cwd、git status、最近命令喂给 LLM，让「把这些改动提交了」生成正确的 git add/commit。依赖 Shell 集成拿 cwd。
    依赖 Shell 集成
  • 7
    危险命令分级 ★
    rm -rf / sudo / dd / git push -f 等在待确认区高亮红框 + 二次确认。把已有安全阀升级成「风险感知的安全阀」。
    安全天然优势
  • 8
    语音修正 / 追加
    说「不对，是 8080 端口」时改写待确认区，而不是重来。
  • 9
    语音朗读输出（TTS）
    命令报错或长输出时可选朗读。真正的 voice 终端应双向；无障碍场景加分。
    AVSpeechSynthesizer无障碍
