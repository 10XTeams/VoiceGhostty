# 手机遥控

状态:设想,有界面原型,未开工。记录于 2026-11-21。

## 要解决什么

人不在 Mac 前(沙发上、另一个房间)时,用手机给正在跑的 Claude Code 发指令、看它做完没有、应答它的确认提示。

## 方案

```
手机浏览器 ──WebSocket(局域网)──> 服务线程 ──channel──> App 主循环 ──> session.write() ──> 窗格
          <──── 窗格列表 / 状态灯 / 屏幕文本 ────
```

- **Mac 端**:新 crate `vg-remote`,独立线程监听端口。项目是线程 + 阻塞 IO,用同步的 `tungstenite`,不引入 tokio。
- **接入点**:服务线程把指令丢进 channel 并 `ctx.request_repaint()`,`App` 每帧取出,走和语音上屏相同的路径写进窗格。
- **手机端**:服务顺带托管一个静态网页,浏览器打开即可,不做原生 App。
- **配对**:设置里显示二维码(`http://<局域网地址>:<端口>/?token=…`),扫码即连。

## 协议(JSON)

| 方向 | 消息 | 用途 |
|---|---|---|
| 手机 → Mac | `send_text {pane, text, enter}` | 往指定窗格发指令 |
| 手机 → Mac | `send_key {pane, key}` | Esc、Ctrl-C、方向键、回车 |
| 手机 → Mac | `audio {pane, wav}` | 手机录音,交给 Mac 的 whisper 转写(第三期) |
| Mac → 手机 | `panes [{id, title, status}]` | 窗格列表和状态灯,变化时推送 |
| Mac → 手机 | `screen {pane, text}` | 窗格最后 N 行文本 |
| Mac → 手机 | `attention {pane}` | 任务完成或需要确认,复用 `monitor.rs` 的判定 |

## 必须守住的约束

这等于在局域网上开了一个远程 shell,以下几条不能省:

- 默认关闭,设置里手动开启,界面写明「允许局域网内的设备向终端发送命令」。
- 没有 token 的连接一律拒绝,不提供免认证选项;token 可在设置里一键作废。
- 只在局域网内,不经任何第三方服务器中转,终端内容和录音不离开用户自己的设备。
- 文档写明:明文 HTTP 下同网段可嗅探 token 和终端内容,不要在公司或公共 Wi-Fi 上开启。
- token 等同于账号访问权,不能给别人用(会构成 Claude 账号共享)。

## 未决问题

- **手机麦克风**:浏览器只在 HTTPS 下给麦克风权限,局域网明文 HTTP 拿不到。第一期用手机键盘自带听写;
  第三期要在自签 HTTPS 和 Tailscale 之间选一个。
- **macOS 防火墙**:应用是 ad-hoc 签名,用户开着防火墙时系统会弹窗问是否允许传入连接,重新构建后可能要再点一次。
- **端口**:避开 5000 和 7000(隔空播放接收占用)。
- **路由器 AP 隔离**:开了的话手机连不上,需要在文档里提示。
- **依赖**:`tungstenite` 和二维码库都是 MIT/Apache,与本项目 MIT 兼容;动手前先确认能从 crates.io 拉下来。
